# 你爱我=我爱你？词向量演进史

> 同一组三个字，语序一换，意思天差地别。遗憾的是，在最基础的文本表示眼里，这两句话一模一样。本文把文本表示如何一步步「装上」语义讲透，每个阶段的核心公式都会拆开解释。

## 引子：机器眼里的「你爱我」

「你爱我」和「我爱你」是同一组词的两种排列：主语宾语互换，情感方向完全反转。

但对计算机来说，文字只是一串符号。想让模型处理语言，第一步永远是同一件事：把词变成数。

问题在于怎么变。最粗糙的表示方法根本分不清这两句话——它们出现的词完全相同。这就是文本表示要解决的起点，从这个起点走到今天的 BERT，人类用了半个多世纪。

每一代方法都在解决上一代的核心瓶颈。顺着这条线看下去，你会发现 Transformer 和 BERT 不是凭空出现的，而是被一个个具体问题「逼」出来的。

## 一、词袋模型：把文本扔进一个袋子

独热（One-Hot）表示是最早的尝试：词表有多大，向量就有多长。只有该词所在的位置是 1，其余全是 0。

它有两个致命问题。第一，向量之间没有语义：「猫」和「狗」的距离，与「猫」和「桌子」的距离完全相同。第二，维度灾难：词表 10 万个词，每个词就是 10 万维向量，其中 99.99% 的位置是 0。

词袋模型（Bag of Words，BoW）前进了一小步：不再表示单个词，而是统计整篇文档中每个词出现的次数，得到一个词频向量。

```python
from sklearn.feature_extraction.text import CountVectorizer

corpus = ["你爱我", "我爱你"]
vectorizer = CountVectorizer(analyzer="char").fit(corpus)
print(vectorizer.transform(corpus).toarray())
# 两句话得到完全相同的向量
```

（示例按单字切分仅为演示，中文实际需先分词。）

代价是词序被彻底扔掉。「你爱我」和「我爱你」在词袋眼里完全相同——袋子里的词确实一样。

还有一个问题：词频不等于重要性。「的」「是」「了」这类词几乎出现在每篇文档里，词频很高，却携带最少的信息。

## 二、TF-IDF：从「出现过」到「有多重要」

TF-IDF 给每个词打上重要性权重，思路很直接：一个词在当前文档里出现得多、在其他文档里出现得少，就越能代表这篇文档。

它由两部分相乘：

- **TF（词频）**：`TF(w, d) = 该词在文档 d 中出现的次数 / 文档 d 的总词数`，衡量「在这个文档里有多常见」
- **IDF（逆文档频率）**：`IDF(w) = log(N / df(w))`，其中 N 是文档总数，df(w) 是包含该词的文档数，衡量「在整个语料库里有多罕见」

IDF 为什么要取 log？两个原因。一是 N 往往很大，直接用 N/df 会让罕见词的权重失控；log 把数值压缩到温和区间，只保留谁大谁小的相对关系。二是语料库增长时权重平滑变化，不会因为文档翻倍就跳变。

相乘之后，「的」「是」这类高频词的 IDF 接近 0，权重被自动压制；「分布式表示」这种只出现在少数文档里的关键词，权重被放大。

TF-IDF 的局限也很明显：它仍然只统计词出现与否、出现多频繁，依然没有语义，也依然忽略词序。

## 三、N-gram：给词袋装上一点记忆

词袋丢掉了词序，能不能捡回来？N-gram 的思路是把「连续 n 个词」当作一个新词。

- **Unigram（1-gram）**：单个词，等价于词袋模型
- **Bigram（2-gram）**：相邻两词的组合，如「你爱」「爱我」
- **Trigram（3-gram）**：相邻三词的组合，如「你爱我」

有了 bigram，「你爱我」包含「你爱」和「爱我」，「我爱你」包含「我爱」和「爱我」——两句话的向量终于不同了，局部词序被捕捉到了。

但代价立刻出现：维度爆炸。Unigram 的维度是词表大小 V，bigram 的维度是 V²。取 V = 10 万，bigram 向量就有 100 亿维，其中绝大多数位置仍然是 0。n 越大，组合数按 Vⁿ 增长，稀疏性越严重。

而且无论 n 多大，它捕捉的只是连续 n 个词的局部搭配，依然理解不了「猫喜欢鱼」和「鱼喜欢猫」的区别——语义仍然缺席。

统计词频、加权、拼局部词序，三条路都试过了。表示形式始终是高维稀疏向量，语义始终不在其中。真正的转折点是换一个思路：不让人工设计特征，让神经网络从海量文本里「学」出向量。

## 四、Word2Vec：语义第一次可计算

2013 年，Google 提出 Word2Vec，基于一个语言学假设——分布假说（Distributional Hypothesis）：**一个词的含义，由它的上下文决定**。经常出现在「猫」「狗」「鱼」附近的词，大概率也是动物；经常出现在「吃」「喝」「咬」附近的词，大概率是动作。

Word2Vec 用一个仅有一层隐藏层的神经网络实现这个思想，有两种训练模式：

- **CBOW（连续词袋）**：用上下文预测中心词，比如用「我 ___ 你」预测「爱」
- **Skip-gram**：反过来，用中心词预测上下文，用「爱」预测出「我」和「你」

训练目标可以写成一个条件概率。对上下文 context 中的中心词 w：

```
P(w | context) = exp(v_w · h) / Σ_v exp(v_v · h)
```

其中 h 是上下文的向量表示，点积 v_w · h 衡量候选词向量与上下文的相似度；分母对整个词表归一化，把分数变成概率分布。损失就是交叉熵：`loss = −log P(w | context)`。直觉很朴素：不断调整每个词的向量，让上下文出现时、正确词的概率尽可能大。

实际训练中，对整个词表归一化太慢，工程上用负采样（Negative Sampling）把多分类简化成「是 / 否」判断：正确词是正例，随机抽几个错误词当负例，效率大幅提升。

训练完成后，词向量作为副产物被留下来：每个词变成 50～300 维的稠密向量，语义和语法关系直接体现在向量的方向和距离上。于是有了那个著名的结果：

```
king − man + woman ≈ queen
```

「国王」减去「男性」加上「女性」，得到「女王」。语义第一次变成了可以做算术的几何对象。

但 Word2Vec 有一个根本局限：每个词对应一个固定向量，训练完就不再变化。「打」在「打电话」和「打游戏」里是同一个向量——一词多义无法处理。要让向量看上下文说话，需要更强的序列建模能力。而当时统治序列建模的 RNN/LSTM 有天然缺陷：必须从左到右串行计算，长距离依赖还容易丢失。

## 五、注意力机制与 Transformer：并行革命

注意力机制（Attention）的想法很直观：处理一个词时，不只盯邻近位置，而是**看全局，按相关性加权**——谁跟我关系大，谁的权重就大。

这个思想的公式表达就是 Transformer 的核心：

```
Attention(Q, K, V) = softmax(QKᵀ / √d_k) V
```

拆开是三步：

1. **算相关性**：Q（查询）与 K（键）做点积，QKᵀ 得到每个词对每个词的相关性分数
2. **缩放**：除以 √d_k。维度高时点积数值会很大，softmax 输入过大后输出趋近 one-hot，梯度几乎为零；缩放让分数回到 softmax 的灵敏区间
3. **加权聚合**：softmax 把分数归一化成和为 1 的权重，对 V（值）加权求和，得到融合了全局信息的新表示

2017 年的 Transformer 完全基于注意力构建序列模型，抛弃 RNN 的串行结构：任意两个位置之间的依赖一步直达，整个序列并行计算。训练速度和长距离建模能力同时起飞，从此成为 NLP 的底座架构。

不过 Transformer 本身只是「引擎」。用什么任务训练它，才能让它学会通用的语言理解？

## 六、BERT：预训练 + 微调范式

2018 年，Google 的 BERT（Bidirectional Encoder Representations from Transformers，基于 Transformer 的双向编码器表示）给出答案：先在海量文本上预训练，再在具体任务上微调。

预训练的核心任务是掩码语言模型（Masked Language Model，MLM）：随机把句子中 15% 的词遮住，让模型根据上下文预测被遮的词。这逼着模型同时利用前后文——双向理解，正是它与 GPT（单向、只看前文）的关键分野。

一个容易被忽略的细节：这 15% 的词并非全换成 [MASK]，而是 80% 换成 [MASK]、10% 换成随机词、10% 保持原词。原因是防止模型偷懒——如果被遮位置总有特殊标记，模型可以只在标记出现时才认真预测；掺入随机词和原词后，它必须真正理解每个词的上下文才能答对。这也缓解了预训练（有 [MASK]）与微调（没有 [MASK]）之间的形式差异。

BERT 之后，词向量的概念被彻底改写：向量不再是词的固定属性，而是句子的函数。同一个「打」字，在不同句子里得到不同向量——一词多义被动态表示解决。

## 七、一张表看懂演进史，以及现在该怎么选

| 方法 | 年代 | 表示形式 | 核心进步 | 遗留瓶颈 |
|------|------|----------|----------|----------|
| 词袋模型 | — | 高维稀疏词频 | 简单可计算 | 无语义、丢词序 |
| TF-IDF | — | 稀疏加权向量 | 区分词的重要性 | 无语义、丢词序 |
| N-gram | — | 稀疏组合向量 | 局部词序 | 维度爆炸 |
| Word2Vec | 2013 | 低维稠密向量 | 语义可计算 | 静态向量、一词多义 |
| Transformer | 2017 | 上下文动态表示 | 全并行、长距离依赖 | 需要训练任务设计 |
| BERT | 2018 | 上下文动态表示 | 双向理解、预训练范式 | 计算成本高、生成弱 |

演进主线浓缩成一句话：**每一代都在解决上一代的核心瓶颈**——稀疏到稠密、静态到动态、单向到双向。语义信息的密度一路上升，表示形式也从人工设计统计特征走向端到端学习。

选型不必盲目追新：小数据、要可解释，TF-IDF 加线性分类器依然是强基线；需要词级语义相似度，Word2Vec/GloVe 依旧够用；要真正理解语义，微调 BERT 或直接调用大模型 API。

回看开头：「你爱我」和「我爱你」，今天的 BERT 会给它们两组完全不同的向量。从「一模一样」到「完全不同」，这段路程正是文本表示半个多世纪演进的缩影。
