# 大模型应用技术栈

> 大模型应用的完整链路：以 [[大语言模型]] 为基座，用 Prompt 与 RAG 降低使用门槛，用微调与对齐适配领域，用评测与安全护栏保证可用。

## 背景

预训练语言模型（见 [[NLP模型演进与核心任务]]）解决了"有没有智能"的问题；应用技术栈解决"怎么用起来"的问题。整条链路围绕一个核心矛盾展开：预训练模型是通用的，而业务需求是具体的。

## 链路总览

| 层 | 组件 | 解决什么 |
|----|------|----------|
| 基座层 | [[大语言模型]] | 通用能力来源：token 化、预训练、规模定律（Scaling Law）与 MoE 架构 |
| 使用层 | [[Prompt工程]] | 零成本引导模型产出；[[提示词注入]] 是其安全边界 |
| 增强层 | [[RAG]] + [[向量数据库]] | 接入外部知识，缓解幻觉与知识过时，无需改模型 |
| 适配层 | [[微调]]（LoRA/PEFT） | 领域风格与任务特化；[[RLHF]] 进一步对齐人类偏好 |
| 保障层 | [[LLM评测]] | 基准 + 自定义评估集 + 红队测试，改动前后量化验证 |

## 关键选型逻辑

- **Prompt vs RAG vs 微调**：先试 Prompt，知识不足上 RAG，风格/任务特化才微调——三者可叠加而非互斥
- **RAG 与微调的分工**：RAG 管"知识"（可随时更新），微调管"能力与风格"（改变模型行为）
- **对齐在微调之后**：SFT 之后接奖励模型与 PPO，让模型行为贴合人类偏好
