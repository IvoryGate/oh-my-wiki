## 定义

Harness 是指围绕 Agent 构建的 **测试、验证与约束基础设施**。

## 四个核心组成部分

| 组成部分 | 作用 |
|----------|------|
| **验收基线** | 明确什么是"完成" |
| **执行边界** | 定义 Agent 可以做什么 |
| **反馈信号** | 告诉 Agent 做对还是做错 |
| **回退手段** | 失败后如何恢复 |

## 核心判断

> **模型虽然重要，但决定系统能不能稳定运行的，往往是这些外围工程条件。**

这个判断在：
- **高可验证任务**（代码编写）→ Harness 更关键
- **弱验证任务**（开放式研究、多轮协商）→ 模型上限更关键

## 任务四象限

|  | 目标明确 | 目标模糊 |
|--|----------|----------|
| **可自动验证** | ⭐ 最适合 Agent 发挥 | 系统高效往错误方向跑 |
| **需人工验收** | 吞吐量天花板是人的审查速度 | Agent 基本起不到作用 |

**Harness 的目标**：把任务推进右上角（目标明确、可自动验证）

## OpenAI 的 Agent 优先开发实践

3 个工程师 5 个月写了百万行代码，将近 1500 个 PR，是传统开发速度的 10 倍。关键决策：

1. **Agent 看不到的内容等于不存在**：知识必须存在于代码库本身
2. **约束编码化而非文档化**：编码进 Linter、类型系统或 CI 规则里
3. **Agent 端到端自主完成任务**：全链路不需要人介入
4. **最小化合并阻力**：测试偶发失败用重跑处理而不是阻塞进度
