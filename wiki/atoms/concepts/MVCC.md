# MVCC

## 核心定义

MVCC（多版本并发控制）让**一致性读不用加锁**：每一行数据都带有事务版本信息，读操作按"一致性读视图"判断哪个版本对自己可见。

## 三个基础件（08 篇）

1. **事务 id**：InnoDB 在事务**第一次执行写语句**时分配（不是 begin 时刻）
2. **row trx_id**：每个行版本记录"最后一次修改它的事务 id"——**用户 id、事务 id、row trx_id 是三套不同的编号体系**
3. **一致性读视图（read view）**：事务执行第一个**一致性读**（快照读）的瞬间创建，此后该事务内的所有快照读都复用它

## 可见性判断的三色规则

视图维护**当前活跃事务 id 数组**与**水位（up_limit_id / low_limit_id）**：

- 事务 id **小于水位且不在活跃数组** → 已提交，**可见**
- 事务 id **大于等于水位** → 事务在快照后才开始，**不可见**
- 事务 id **在活跃数组中** → 尚未提交，**不可见**
- 不可见的版本沿**版本链**（undo log 串联）继续找上一版本，直到可见

## RR 与 RC 的关键差异

| | RR | RC |
|---|----|----|
| read view 创建时机 | 事务内**第一次一致性读**时创建，整个事务复用 | **每条语句**都重新创建 |
| 结果 | 事务内快照读结果一致 | 能读到别的事务已提交的最新数据 |

## 与"隔离的假象"

- 快照读读旧版本 → 看起来"改了我看不见"
- **更新/当前读读最新版本** → 所以 RR 并不能靠 MVCC 消除幻读，范围的当前读仍需加锁（见 [[幻读]]、[[间隙锁]]）
- undo log 既要支撑 MVCC，也要支撑回滚 → 这是"长事务有代价"的根本原因
