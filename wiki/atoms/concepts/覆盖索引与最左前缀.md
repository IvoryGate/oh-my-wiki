# 覆盖索引与最左前缀

## 覆盖索引

**定义**：查询**结果里需要的字段全部包含在索引中**，无需回表。

- **`EXPLAIN` 判据**：`Extra` 出现 **`Using index`**
- 例（05）：联合索引 `(id, name)`，`select id, name from t where name='xxx'` → 覆盖，不回表
- 与 [[回表]] 是同一枚硬币的两面：**覆盖 = 不回表**

**`select *` 是覆盖索引的头号破坏者**（16）：即使排序字段在索引里，`select *` 也要回表 → 退化成 filesort；想要覆盖就只查需要的列。

## 最左前缀

**定义**：联合索引 `(a,b,c)` 的匹配**必须从最左连续字段开始**。

| 能用上索引 | 用不上索引 |
|-----------|-----------|
| `where a = ?` | `where b = ? and c = ?` |
| `where a = ? and b = ?` | `where a = ? and c = ?` |
| `where a = ? and b = ? and c = ?` | `where b = ?` |

原文口径：**"如果用了 b 或 c 但没用 a，索引就失效"**。

**索引复用**（04）：建了 `(a,b)` 相当于同时拥有 `(a)` 和 `(a,b)`——最左前缀让一个联合索引服务多个查询模式，这是"组合索引性能提升 10 倍"（宝典 10）的原理来源。

## 字段顺序三口诀（11 篇）

1. **区分度大的放前面**——先过滤掉更多行
2. **字段小的放前面**——一页放更多，减少 IO
3. **查询频率高的放前面**——让最常跑的查询命中更左的前缀

## 索引下推：前缀匹配的补丁（05，MySQL 5.6 引入）

联合索引 `(name, age, sex)` + `where name like '张%' and age=10 and sex='M'`：

- **不支持 ICP**：按 `name` 前缀取出全部元数据 → **回表** → 再过滤 age/sex
- **支持 ICP**：InnoDB 在**索引层**就判断 `age=10 and sex='M'` → **减少回表次数**

即把"先过滤"下推到存储引擎层执行，`EXPLAIN` 的 `Extra` 显示 **`Using index condition`**。

## 一个容易忽略的限制：前缀索引不能排序

只索引了字段前 N 个字符（如 `email(4)`）时，索引里不再有完整的字段值 → **无法用于 ORDER BY 和分页**，且定长变变长会让回表变慢。因此原文给出口诀**"宁可索引长一点"**（详见 [[索引选择性]]）。
