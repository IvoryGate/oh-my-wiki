# 聚簇索引

## 核心定义

**聚簇索引（主键索引）的叶子结点存的是整行数据**——表的数据文件本身就是一个按主键构造的 B+ 树。宝典 09 称之为**索引组织表（Index-Organized Table）**："万物皆索引"，数据即索引、索引即数据。

> 45讲 04 的原话方向：数据文件本身是按主键组织的 B+ 树，所以"主键索引"不是额外的索引，而是**数据的组织方式**。

## 两类索引的分工

| | 聚簇索引（主键索引） | 二级索引 |
|---|---|---|
| 叶子结点存 | **整行数据** | **主键值** |
| 查询整行 | 直接返回 | 必须**回表**（见 [[回表]]） |
| change buffer | **不适用** | **适用**（普通索引） |
| 数量 | 一张表 1 个 | 可多个 |

## 普通索引 vs 唯一索引（09 篇）

- **查询**：性能差异**可忽略**——InnoDB 按页读取，多读的行已在同一数据页内
- **更新**：
  - **普通索引**可利用 **change buffer**，把对二级索引页的变更先记下来，merge 时才读盘
  - **唯一索引**必须**读页做唯一性校验**（判断表中是否已存在记录）→ 失去了 change buffer 的收益
- change buffer 的边界：
  - `innodb_change_buffer_max_size` 默认 **50**（占 buffer pool 的 50%）
  - **只对二级索引有效，对主键索引无效**
  - **唯一索引不使用 change buffer**
  - "离索引页越远，merge 操作越节约 IO"
- 写入路径口径（09）：WAL → Change Buffer → Buffer Pool → 磁盘；binlog 只在事务提交后写一次

## 主键选择的隐含约束

结合 [[B+树索引]] 的页分裂：**自增主键 + NOT NULL** 能让插入始终追加到最右页，避免页分裂——这与"INT 做业务主键在双 11 场景不可取"（宝典开篇）并不矛盾：**技术上自增主键结构最优，业务上需要全局唯一 ID 时要另做权衡**。
