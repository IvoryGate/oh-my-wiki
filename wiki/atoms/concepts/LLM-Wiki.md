# LLM Wiki

> 一种使用大语言模型构建个人知识库的模式：LLM 增量构建并维护一个持久 wiki，知识"编译一次，持续保鲜"

## 核心定义

LLM Wiki 是 Andrej Karpathy 提出的知识管理模式。核心思想是：**让 LLM 将原始资料"编译"成结构化的知识网络，而不是每次查询时重新检索原始文档。**

传统 RAG 每次提问都从零重新发现知识，没有积累——需要综合五份文档的微妙问题，每次都要重新找到碎片拼接。LLM Wiki 的做法不同：新资料入库时，LLM 阅读它、提取关键信息、融入既有 wiki——更新实体页、修订主题摘要、标记新旧矛盾、强化或挑战既有综合。**wiki 是一个持久的、复利增长的制品**：交叉引用已经就位，矛盾已被标记，综合已反映全部已读内容。

## 与 RAG 的本质区别

| 传统 RAG | LLM Wiki |
|----------|----------|
| 解释器模式 | 编译器模式 |
| 查询时重新检索 | 入库时预先编译 |
| 知识不积累 | 知识复利增长 |
| 无持久化结构 | 生成中间表示 |

## 三层架构

```
Raw Sources     →  原始资料（只读，真相来源）
The Wiki        →  结构化知识（LLM 维护，人只读）
The Schema      →  配置规则（AGENTS.md 等，人机共同演化）
```

Schema 是关键配置文件：它让 LLM 成为有纪律的 wiki 维护者，而非通用聊天机器人。你和 LLM 随着实践共同演化这份规则。

人几乎从不亲手写 wiki——LLM 写并维护全部内容。人负责策展来源、引导探索、提出好问题；Obsidian 是 IDE，LLM 是程序员，wiki 是代码库。

## 核心操作

### Ingest（入库）
新资料进入 raw → LLM 阅读理解 → 与用户讨论关键收获 → 写摘要页 → 更新相关实体/概念页 → 维护索引和日志。一篇资料可能触及 10-15 个 wiki 页面。可逐篇入库保持参与，也可批量入库。

### Query（查询）
基于已编译的知识回答，带引用。答案形式随问题而变：页面、对比表、幻灯片（Marp）、图表、canvas。**高质量答案可归档为新页面**——对比、分析、发现的联系不应消失在聊天记录里，让探索像入库资料一样复利。

### Lint（体检）
定期健康检查：页面间矛盾、过时论断、孤立页面、被提及但无独立页的缺失概念、缺失交叉引用、可通过搜索补齐的数据缺口。

## 两个特殊文件

- **index.md（内容导向）**：全库目录，每页一行摘要。查询先读 index 定位再深入页面——中等规模（约百份来源、数百页）下效果出人意料地好，无需向量检索设施
- **log.md（时间导向）**：只追加的操作记录。统一前缀（如 `## [日期] ingest | 标题`）后可用 grep/tail 解析出最近操作，也帮 LLM 理解最近做过什么

## 为什么可行

维护知识库最累的不是阅读和思考，而是**记账**：更新交叉引用、保持摘要新鲜、标记矛盾、跨几十页保持一致。人放弃 wiki 是因为维护负担增长快于价值。LLM 不会厌烦、不会忘记更新某条链接、一次能改 15 个文件——**维护成本趋近于零，wiki 才能保持被维护**。

> "读文章、判断价值、决定方向——这些是人该干的事。整理格式、更新链接、维护索引——这些 bookkeeping 的活，交给 AI 干最合适。"

## 思想渊源

与 Vannevar Bush 的 **Memex**（1945）一脉相承：私人、主动策展的知识库，文档间的关联路径与文档本身同样有价值。Bush 没能解决的是"谁来维护"——LLM 补上了这一环。

## 适用场景

- **个人成长**：目标、健康、日志、文章的结构化自我画像
- **研究深潜**：数周数月的论文报告积累出不断演化的综述
- **读书 companion**：逐章建人物/主题/情节页，读完即得粉丝维基级伴读库（如 Tolkien Gateway）
- **团队内部 wiki**：Slack 记录、会议纪要、项目文档由 LLM 维护，人把关
- **竞品分析、尽调、行程规划、课程笔记**——任何随时间积累、需要组织而非散落的知识

## 工具与技巧

- **搜索**：小规模用 index 足够；长大后用 [qmd](https://github.com/tobi/qmd)（BM25/向量混合、离线、CLI + MCP）
- **剪藏**：Obsidian Web Clipper 一键存 raw；图片下载到本地目录（如 `raw/assets/`），LLM 先读文本再分步查看图片
- **展示**：Marp 生成幻灯片、Dataview 基于 frontmatter 动态查询、graph view 观察结构与孤立页
- **版本**：wiki 就是 git 仓库，历史、分支、协作免费获得
- 文档刻意抽象：目录结构、页面格式、工具链都按你的领域和偏好实例化，挑有用的用，忽略没用的
