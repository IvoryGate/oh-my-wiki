# 软件工程

> 用工程化的方法开发维护软件，让项目按时完成、成本可控、质量有保证

## 核心定义

软件工程 = 过程 + 方法 + 工具

- **过程**：软件项目生命周期（规划→需求→设计→编码→测试→维护）
- **方法**：各阶段的方法学（如需求分析、软件测试）
- **工具**：源代码管理、持续集成、看板等

## 起源：软件危机

1968 年北大西洋公约组织（NATO）会议为解决"软件危机"，首次提出"软件工程"概念。

**软件危机**：60 年代软件规模扩大后暴露的开发维护问题——

- 产品质量低劣、软件维护工作量大
- 成本不断上升、进度不可控
- 程序员无限度增加

**典型案例**：

- **OS/360**：1000 人年投入，最终无法运行，损失数百万美元
- **Therac-25**：医疗事故，放射剂量 bug 导致患者伤亡

## 过程模型演化

```
瀑布模型 → V模型 → 增量模型 → 螺旋模型 → 敏捷开发
```

### 瀑布模型

传统软件过程模型，按阶段顺序推进：需求 → 设计 → 实现 → 测试 → 交付 → 维护。

- 阶段性强，分工协作清晰
- 只能单向流转，变更成本高
- 周期长，大项目风险高

衍生模型：V 模型（测试提前介入）、增量模型（分批交付）、螺旋模型（风险驱动迭代）。

### 敏捷开发

2001 年敏捷联盟（Agile Alliance）发布《敏捷宣言》，整合 Scrum、极限编程等轻量级方法。

核心原则：

- 个体和互动高于流程和工具
- 可工作的软件高于详尽的文档
- 客户合作高于合同谈判
- 响应变化高于遵循计划

常见框架：**Scrum**（迭代式增量开发）、**极限编程 XP**（测试驱动、结对编程）。

## 经典著作：人月神话

《人月神话》（The Mythical Man-Month），佛瑞德·布鲁克斯（Fred Brooks）1975 年出版，总结其在 OS/360 项目中的管理经验。

- **人月神话**：增加人手不能缩短进度，沟通成本随团队规模指数增长
- **没有银弹**：软件工程没有万能解决方案
- **Brooks 定律**：延后的项目总会延迟

## 工程方法论：工程思维

把任何事当作一个项目，用工程方法有计划、有步骤地解决，站在整体而非局部角度思考。

**工程方法六阶段**：

1. **想法**：定义问题，研究可行性
2. **概念**：提出概念性解决方案
3. **计划**：制定实施计划（人员、任务、时间、预算）
4. **设计**：细化架构，划分功能模块
5. **开发**：迭代构建、实施
6. **发布**：发布最终结果和文档

**核心价值**：有被有效论证的方法论指导，提高成功概率和效率，培养大局观。

**应用场景**：日常工作规划、生活问题解决、学习计划制定、项目管理。
