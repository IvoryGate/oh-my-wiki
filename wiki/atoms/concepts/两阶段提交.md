# 两阶段提交

## 核心定义

两阶段提交是 InnoDB 在提交时把 **redo log 的写入拆成 prepare 和 commit 两步**的机制。原文动机：

> "为了让两份日志之间的逻辑一致"——即 [[redo log]]（物理）与 [[binlog]]（逻辑）必须描述同一批修改，否则崩溃恢复后主备数据会不一致。

## 流程

一条更新语句走完 Server 层执行链路后，进入 InnoDB：

1. 修改数据页，写 **redo log buffer**
2. commit 时先写 **prepare** 状态的 redo log
3. 写 **binlog**
4. redo log 标记 **commit**

**XID** 是 redo log 与 binlog 共有的数据字段，用于把两份日志关联起来。

## 为什么需要它（反证法）

02 篇用反证法说明：若不引入两阶段提交，"在写完 redo log 后、写 binlog 前"发生崩溃，或两者写入顺序错乱，会导致 **MySQL 主备数据不一致**。

## 崩溃恢复规则（15 篇）

15 篇回应读者追问，给出异常重启时的恢复判断：

- 恢复时以 **XID** 关联两份日志
- 关键是判断"处于 prepare 状态的 redo log"是否已有对应的 binlog
- 原文按**时刻 A / 时刻 B**（崩溃点不同）逐一分析各种组合的恢复结果
- 配合 binlog-checksum 验证 binlog 完整性（MySQL 5.6.2+）

## 注意点

- "commit 步骤"是存储引擎状态机的最后一步，与客户端发送的 **commit 语句**是两个不同概念
- 只用 redo log 或只用 binlog 都不行（15 篇专门验证过这两种假设），crash-safe 是两者共同作用的结果
