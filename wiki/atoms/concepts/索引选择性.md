# 索引选择性

## 核心定义

**索引选择性 = 不同值的数量 / 总行数**，衡量一个字段（或其前缀）能把结果集切得多碎。选择性越高，索引过滤能力越强。

## 度量方法（11 篇）

用 `count(distinct left(col, N))` 逐档测试前缀长度：

```sql
select count(distinct left(email, 4)) * 100 / count(*) from user;
```

**判定阈值：达到 85% 即可接受**（原文给的经验值；同篇的另一个口径是 `count(distinct left(email, N))` 接近 `L × 95%`）。

> 含义：不必追到 100% 区分度——前缀索引本来就是在"索引体积"与"区分度"之间做交易，**85% 是性价比拐点**。

## 前缀索引的两个代价

1. **无法用于 ORDER BY 与分页**——索引里只有前缀，排序语义不完整
2. **定长变变长**——每个索引项长度不再固定，回表变慢

**口诀：宁可索引长一点。** 能用完整字段索引就别用前缀。

## 改写示例

```sql
ALTER TABLE user
  DROP INDEX idx_email,
  ADD INDEX idx_email(email(4));
```

## 与"值不重复"相关的两个陷阱

- **区分度低的字段建索引代价大**：如性别、状态这类只有几个取值的列，索引筛不掉多少行，却要维护 B+ 树
- **唯一约束要靠唯一索引**：选择性不足不等于不能建，但要清楚它承担的是**约束职责**而非性能职责（呼应 [[聚簇索引]] 中普通索引可用 change buffer、唯一索引必须校验的差异）

## 关联

选择性只是"该不该建索引"的静态判断；**优化器最终选不选它**还要看统计信息与代价估算（CBO、直方图、`ANALYZE TABLE`），见 [[MySQL索引体系与查询优化]] 第五节。
