# 事务隔离级别

## 核心定义

隔离级别描述**一个事务执行过程中的数据，对其他事务的可见性**，用来在一致性与并发度之间取舍。MySQL 默认 **可重复读（Repeatable Read, RR）**。

## 四种级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|------|------|-----------|------|
| 读未提交 Read Uncommitted | 有 | 有 | 有 |
| 读提交 Read Committed (RC) | 无 | 有 | 有 |
| 可重复读 Repeatable Read (RR) | 无 | 无 | 有 |
| 串行化 Serializable | 无 | 无 | 无 |

## 三类现象

- **脏读**：读到了别的事务**未提交**的数据
- **不可重复读**：同一事务内**两次读同一行**结果不同
- **幻读**：同一事务内**两次按同一条件范围查询**，行数不同

> 原文辨析（20 篇）：幻读专指**范围查询**下新插入的行带来的差异；"快照读读到的是快照，当前读读的是最新版本"——幻读问题只在**当前读**场景下真正产生影响（详见 [[幻读]]）。

## RR 下的两套读

- **一致性读（快照读）**：普通 `select`，读事务开始（首个一致性读）时创建的快照，不加锁，由 [[MVCC]] 支撑
- **当前读**：`select ... for update`、`lock in share mode`、`update`、`insert`、`delete`，读**最新版本**并加锁

原文要点：RR 中**更新语句是当前读**——"如果你在事务 A 中先执行了一条 update，再执行 select，读到的就是别的事务已提交的最新值"。这就是"事务到底是隔离的还是不隔离的"（08 篇）这一矛盾的来源：**对修改而言，读的是最新数据；对快照读而言，读的是旧数据。**

## 长事务的代价

事务提交前，InnoDB 必须保留它的回滚日志（undo log）；即便事务没有更新、只是查询，也要维护 read view。原文建议：

- **事务尽可能快地提交**
- 查询到的行可能被别的事务修改，用 `select ... ... for update` 加锁读更安全
