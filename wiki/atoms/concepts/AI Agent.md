# AI Agent

## 核心定义

AI Agent（人工智能智能体）是一种能够根据目标自主决定部分操作步骤、并调用工具完成任务的 AI 系统。它以大语言模型（LLM）为核心，围绕模型构建工具调用、执行控制和状态管理能力。其重点不是能回答多少问题，而是能够调用工具，把任务一步步完成。

## 与传统 AI 模型的区别

大语言模型主要负责处理输入并生成输出，Agent 则是围绕模型构建的任务执行系统，两者不是替代关系——LLM 通常是 Agent 的核心组件之一。

- **自主性：**普通应用以对话和内容生成为主，Agent 可以持续执行多个操作步骤，在允许范围内自行选择工具及操作顺序。
- **工具使用：**普通应用是否有工具取决于应用是否提供，Agent 的工具调用（Tool Use）通常是核心能力。
- **循环执行：**Agent 可以检查工具返回结果、保存任务状态和中间结果，并据此决定是否继续执行或调整步骤。
- **任务规划：**普通应用根据提示进行推理，Agent 可以把复杂任务拆分成多个步骤并按执行情况调整计划。

需要注意，现代 AI 聊天应用也可能具备工具调用和自动执行能力，普通 AI 助手与 Agent 之间没有绝对的技术界限。

## 核心组成

从功能上看，典型的 LLM Agent 可划分为以下部分（这是便于理解的功能划分，不代表所有 Agent 都采用相同架构）：

- **感知（Perception）：**接收用户输入、环境信息和工具返回结果，整理为模型可处理的上下文。
- **模型（LLM）：**理解任务、分析信息，决定下一步操作并生成工具调用参数。
- **工具（Tools）：**执行搜索、文件操作、代码运行和 API 调用等具体任务。
- **记忆（Memory）：**保存对话上下文、任务状态和需要长期使用的信息。
- **规划（Planning）：**拆解复杂任务，确定执行步骤，并根据结果调整计划。

简单的 Agent 可能只需要模型加工具调用加执行循环，复杂系统才增加长期记忆、任务调度和多 Agent 协作等能力。

## 五层底层架构

从基础大模型到能够执行任务的 Agent，AI 应用可按作用划分为五个层级（教学上的功能划分，并非统一技术标准）：

- **基础模型层（Model）：**LLM、Token、Transformer、Attention，负责模型推理和内容生成。
- **上下文层（Context）：**Prompt、Context Window、Memory、RAG，组织模型输入并补充历史与外部知识。
- **工具层（Tools）：**Tool Calling、API、MCP、Database，连接外部程序、数据源和服务。
- **智能体层（Agent）：**Agent、Planning、Agent Loop，根据目标选择操作，组织多步骤任务并处理反馈。
- **应用层（Applications）：**Skill、Workflow、Automation，将模型和工具能力组合成实际产品与业务流程。

并非每个 Agent 都需要 RAG、MCP 或长期记忆，可按任务规模和业务需求选择组件。

## 执行流程

Agent 的核心工作方式是根据任务目标不断执行操作，并利用执行结果决定下一步做什么。常见实现模式是 ReAct（Reasoning and Acting，推理与行动结合），基本流程为：

1. 接收任务：用户提出需要完成的目标。
2. 分析任务：模型判断需要哪些数据、工具和执行步骤。
3. 调用工具：执行搜索、读取文件、运行代码等操作。
4. 获取结果：读取工具返回信息，判断操作是否成功。
5. 继续执行：根据结果调整后续步骤，直到完成任务或需要人工介入。

这些组件由 Agent Loop（运行循环）组织起来。Agent Loop 不应无限循环，常见终止条件包括任务完成、达到步数/时间/预算限制、执行失败、需要人工确认和用户主动停止。ReAct 也不是唯一模式，实际可采用预定义工作流、任务规划器或其他编排机制。

## 主要类型与特点

按决策机制，智能体可分为反应式（Reactive）、目标导向（Goal-based）、效用型（Utility-based）、学习型（Learning）和多智能体系统（Multi-Agent）等类型，类型之间并不互斥。按任务范围，常见有任务型、编程、浏览器、多模态和多 Agent 系统等 Agent。

其共性特点包括：目标导向、自主执行、环境反馈、持续交互和状态管理。并不意味着 Agent 会在使用中自动更新模型参数——多数应用通过上下文、外部知识库和记忆机制改善后续执行效果。

多 Agent（Multi-Agent）协作可以让多个 Agent 分别承担设计、编码、测试、协调等职责，但会增加上下文交换、协调与冲突处理的成本，简单任务通常单 Agent 更直接。

## 局限与风险

- 结果可能出错：模型可能误解需求、生成错误信息或调用不合适的工具。
- 操作可能失败：网络中断、接口变更、格式不兼容都会导致任务失败。
- 执行成本：复杂任务需要多次模型调用和工具操作，增加时间与费用。
- 权限与安全：工具权限过大时，错误操作可能修改文件、泄露数据。
- 缺少稳定性：同一任务在不同执行过程中可能得到不同结果。

因此应按任务风险设置执行边界，对删除文件、修改数据库、支付、外发信息等高风险操作增加人工确认，并配套执行日志、超时限制、错误重试、权限控制和结果验证。
