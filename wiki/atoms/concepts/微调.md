# 微调

## 核心定义

微调（Fine-tuning）是在已经训练好的通用模型基础上，用某个特定领域（如法律、医疗、客服）的数据继续训练，使其适配专业场景的做法。相比从零预训练，微调成本低得多；它既保留通用能力，又能在特定任务上表现出色，是让通用模型落地产品化的常用手段。

## 为什么需要微调

获得专用模型有三条路线，成本与效果各不相同：

| 方式 | 成本 | 效果 | 适用场景 |
|------|------|------|----------|
| 从头训练 | 极高（百万美元级） | 完全定制 | 创建新的基础模型（仅巨头） |
| Prompt 工程 | 几乎为零 | 不稳定，依赖提示词 | 简单任务、快速验证 |
| 微调 | 中等 | 稳定且专业 | 特定领域任务、产品化 |

选型时要看到 Prompt 工程的局限，也要看到微调并非万能：

- Prompt 工程四个天花板：上下文窗口装不下几百个示例；同一提示词输出不稳定；每次推理都带长提示导致 token 消耗大；预训练数据「拉后腿」使格式遵循不彻底。
- 微调的适用特征：任务定义清晰且输出格式固定；有几百到几千条高质量标注数据（500-5000 条较理想）；需要领域专业性；对响应速度和成本敏感；需严格遵循输出格式。
- 与 [[RAG]] 的分工：任务变化快、只做一次性探索或数据只有几十条时，提示工程更灵活；需要模型随时掌握训练数据之外的最新知识时，走检索增强而非微调。
- 通用判据：数据 < 100 条、任务经常变化、偶尔使用 → 更适合 Prompt；数据 > 500 条、任务相对固定、高频使用 → 更适合微调。

## 全量微调（Full Fine-tuning）

全量微调拿预训练模型的所有参数在任务数据集上继续训练，更新所有权重，学习率需设得很小（如 1e-5 到 5e-5），以免覆盖预训练学到的知识。

- 灾难性遗忘（Catastrophic Forgetting）：因为更新所有参数，模型会逐渐忘记预训练的通用知识，任务表现变好但通用能力下降，甚至失去遵循指令等基本能力。
- 显存需求巨大：训练显存 = 模型参数 + 梯度 + 优化器状态 + 激活值；7B 模型全量微调（FP16）约需 50-60 GB，70B 需要 400+ GB。
- 结论：除非数据量非常大、需要改变模型根本行为，否则应优先考虑参数高效微调。

## 参数高效微调（PEFT 与 LoRA）

PEFT（Parameter-Efficient Fine-Tuning）是一类只训练少量参数的方法的总称。其核心洞察是：预训练模型已包含足够知识，只需「调整」一小部分参数即可适应新任务。

- 好处：显存需求大幅降低；原参数不动故无灾难性遗忘；只保存几 MB 到几百 MB 的新增参数；可训练多个适配器按需加载实现任务组合。
- 主流方法：Adapter（插入小网络）、Prefix Tuning（前缀向量）、Prompt Tuning（软提示）、LoRA（低秩适配）、QLoRA（量化 LoRA）。
- LoRA（Low-Rank Adaptation）：洞察是微调时权重变化量通常是低秩的，故冻结原模型，在注意力层旁增加两个小矩阵 A、B，用 ΔW = BA 表示变化，秩 r 常取 8、16、32；只需训练约 0.4% 的参数即可接近全量微调效果。
- QLoRA：把模型量化到 4-bit（NF4 格式）再加 LoRA，显存再降 75%，RTX 3090/4090 一张消费级显卡即可微调 7B/13B 甚至尝试 70B。
- 最佳实践：首选 LoRA，显存不够就用 QLoRA。

## 数据准备与训练要点

数据准备是微调中最耗时、最关键的部分——数据质量决定模型上限。

- 数据量经验：简单任务 100-300 条，中等任务 300-1000 条，复杂任务 1000-5000 条；先备 500 条高质量数据试跑再迭代。
- 清洗要点：去重、过滤低质量数据、统一格式、平衡分布、防止数据泄露。
- 数据格式：Alpaca 格式（instruction / input / output）最通用，对话任务用 ShareGPT 格式（conversations 多轮）。
- 防过拟合：早停（监控 eval loss）、增加数据、减小 LoRA rank、加 dropout。
