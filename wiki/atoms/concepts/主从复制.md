# 主从复制

## 核心定义

主从复制把主库的变更增量同步到备库。**"复制是数据同步的基础，而二进制日志就是复制的基石"**（宝典 15）；总原理是——**"binlog 的特性确保了在备库执行相同的 binlog，可以得到与主库相同的状态"**（45讲 24）。

## 三步流程

| 步骤 | 内容 | 线程 |
|------|------|------|
| **写入** | 主库执行更新逻辑，**同时写 binlog**（T1） | — |
| **传输** | 备库写到本地文件 = **中转日志 relay log**（T2） | 主库 **Dump 线程** → 备库 **I/O 线程** |
| **重放** | 备库读取 relay log、解析命令并执行（T3） | **SQL / Worker 线程** |

**主备延迟 = T3 − T1**。

宝典 15 的搭建四步：① 创建复制账号 ② 从 Master 拷贝数据（`mysqldump` / `mysqlpump` / **Clone Plugin**）③ `CHANGE MASTER TO` ④ `SHOW SLAVE STATUS` 观察。

## 复制类型

- **异步**：Master 不关心 Slave 是否收到，性能最好
- **半同步**：Master 提交过程中至少 N 个 Slave 收到 binlog
  - **有损（5.7 之前）**：WAIT ACK 在**提交之后** → 宕机丢最后一批
  - **无损（5.7）**：WAIT ACK 在**提交之前**（`rpl_semi_sync_master_wait_point = AFTER_SYNC`）→ 金融业务必用
- **多源复制**：N 主 1 从，用于 OLAP 统计
- **延迟复制**：`CHANGE MASTER TO master_delay = 3600`，防误操作的"24 小时前快照"

## 格式决定正确性

| 格式 | 风险 |
|------|------|
| **statement** | 可能主备走不同索引（`delete ... limit 1`）→ 不一致；线上仍用它"基本上就可以认为这是一个不合理的设置" |
| **row** | 记真实变更行，**必然一致**，且**让不一致更容易被发现** |
| **mixed** | 自动判断；依赖上下文的语句额外记 `SET TIMESTAMP=...` |

**推论**：恢复数据要整段 `mysqlbinlog` 输出交给 MySQL 执行；`statement` 会自动补 `use '库名'`。

## 循环复制（双 M）

靠 binlog 中的 **server id** 判重：两库 server id 必须不同，收到与自己相同 server id 的日志直接丢弃。迁移场景用 `CHANGE MASTER TO IGNORE_SERVER_IDS=(...)`。

## 延迟的四类成因

1. 备库机器性能差（含"非双 1"参数）
2. 备库压力大（兼做读与后台分析）
3. **大事务**——主库等事务完成才写 binlog（1 亿条删除可能产生 **100G binlog**、等 **1000 秒**）
4. **并行复制能力不足**（**5.7 之前回放是单线程**，5.6 是库级单线程）

**并行复制**：`sql_thread` 拆为 **coordinator**（只分发）+ **worker**（真正执行）；两条顺序约束——同行更新必须同 worker、同事务不能拆。`slave_parallel_workers` 建议 **8~16**；**`WRITESET` 模式**下"主机单线程、从机也可多线程并行回放"：

```sql
binlog_transaction_dependency_tracking = WRITESET
transaction_write_set_extraction      = XXHASH64
slave-parallel-type                   = LOGICAL_CLOCK
slave-parallel-workers                = 16
```

## crash safe 六个必配参数（宝典 15）

```
gtid_mode = on                      enforce_gtid_consistency = 1
binlog_gtid_simple_recovery = 1     relay_log_recovery = ON
master_info_repository = TABLE      relay_log_info_repository = TABLE
```

> "请确认上述参数都已配置，否则任何的不一致都不是 MySQL 的问题，而是你使用 MySQL 的错误姿势所致。"
