1.一条SSP发来的用户设备上的ad request都包含哪些信息？

首先，不熟悉RTB竞价的朋友们，可以先去看（一）中讲述的详细内容。这里只放两张图，简述一下RTB的流程：

用户设备上发起广告位的广告请求（0）到ADX平台，ADX平台将这一条广告请求转发（1）给对接的各家DSP。各家DSP收到请求后，根据接收的Request和自己的数据库建模，选择是否有合适的广告参与竞价，竞价的话就把ad和bid price返还（2）给ADX。ADX在自己内部完成竞价（3）并将最终收费的金额发送给DSP（4），同时将胜出的Ad下发给用户设备（5）。用户界面会监测这条广告是否展示加载成功以及是否有点击，并将这一行为发送给DSP。

注：

i.广义二价auction中，最高bid赢得机会但收费为第二高DSP的bid；

ii.无论竞价是否成功，都会给各家DSP发送auction结果；

iii.目前在广告展示环节，大多数监测链接会发送给三方监测平台，一般为异步监测；

在广告行业中，一条ad request（广告请求）是指广告平台从用户设备发送到广告服务器，用于请求展示广告的消息。通常，它会包含各种与用户、设备、上下文等相关的信息，以便广告服务器能够根据这些信息返回最匹配的广告。

真实的技术中，一条ad request就是一个JSON格式的文件，举个例子：

```javascript
{   "user": {     "user_id": "UID12345XYZ",     "location": {"latitude": 37.7749, "longitude": -122.4194},     "interests": ["sports","technology"]   },   "device": {     "type": "smartphone",     "os": "iOS 17.1",     "browser": "Chrome v118",     "device_id":"IDFA1234-5678-ABCD"   },   "network": {     "ip_address": "192.168.0.1",     "network_type": "WiFi",     "timezone": "GMT+8"  },   "app": {     "app_id": "com.example.app",     "url": "https://example.com/news",     "slot": {"slot_id": "banner_1", "size":"300x250"}   },   "ad_request": {     "format": "video",     "min_bid": 0.05,     "creative_type": "non-intrusive",     "max_duration": 30   }}
```

我们根据Real-Time Bidding Benchmarking with iPinYou Dataset中的论文介绍，我们以他的数据集中的日志数据（log data）为例（该数据是bid log和imp/click/cr log的合集；其中有\*的列是哈希值；有†的列仅在imp/click/cr log中存在）：

![图片](https://mmbiz.qpic.cn/mmbiz_png/ofNjybZfTIBHNmQ9PsTXCpIUJXmYnLgVydbTXeLpOzTic4GPm20qsEMWTO7PPfD8DpTUibw5plR3WKFK0uWhecLw/640?wx_fmt=png&from=appmsg&tp=webp&wxfrom=5&wx_lazy=1#imgIndex=2)

注：

(c01)：这条bid的唯一ID

(c02)：这条bid的时间戳

(c03)：日志记录的类型，可能为impression或click或conversion

(c04)：iPinYou这个app记录的内部CUID

(c05)：用户设备和操作系统信息

(c06-c08)：用户IP地址

(c09)：参与竞价的ADX

(c10)：广告位的网页主域名

(c11)：广告位的网页URL

(c12)：匿名URL，仅当DSP中的(c11)不可用时

(c13-c15)：广告位基础信息

(c16)：广告位在该设备上被第几次观看

(c17)：广告位的形式为固定or弹出&背景等信息

(c18)：广告位的floor price

(c19)：胜出DSP的素材ID

(c20)：bid price

(c21)：win price，又叫做clearing price

(c22)：主页URL

(c23)：广告主ID

(c24)：在iPinYou数据库中的用户标签

2.为什么IAB伟大？在OpenRTB环节中，它起什么作用？

上面讲述了一个最最基础的Ad Request都包含哪些环节。但是我们知道，现在大家都参与OpenRTB，如果每个SSP中自己的request都不一致，那么ADX平台就需要每次单独配置对接不同的SSP。这个的工作量实在太大了，这极大阻碍了广告竞价的效率！

说到这里就不得不提IAB了，为什么说IAB伟大呢？它不光创建以统一的广告Open RTB竞价协议，还创建了一套非常完善的标准！

不管是MRAID或者DAPI等互动文件素材的协议；还是Request和Response的参数标准；抑或是各家DSP的App-ads.txt文件......

都做了明确的规范，让大家统一遵守！

IAB官网：https://www.iab.com/

IAB Tech Lab：https://github.com/InteractiveAdvertisingBureau/openrtb2.x/blob/develop/2.6.md#321---object-bidrequest-

感兴趣的同学，可以阅读一下官网的Github文档。我们以2.6版本的Bid Request Specification为例，它甚至定义了device的可选列表、素材的语言限制IETF BCP 47I以及广告主内容的品类可选类型taxonomy等：
