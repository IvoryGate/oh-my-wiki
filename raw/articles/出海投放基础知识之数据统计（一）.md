应用如何查询并统计用户的活跃状态？

不论是甲方的用户运营，买量优化师还是乙方的客户经理，知道单个用户每日的活跃状态，是至关重要的。通过这个指标对用户分层可以帮助用户运营对不同的用户采取不同的策略，比如不活跃的用户采用弹窗的方式促活；可以帮助产品统计整体用户的DAU(Daily Active Users)或者MAU(Monthly Active Users)并计算整体产品的更新方向；可以帮助买量优化师了解忠实用户(loyal user rate)的比例；对于乙方平台的客户经理来说，了解活跃状态可以帮助计算用户的留存率(Retention Rate)来优化广告投放计划的效果。

这里需要解释一个新的技术概念：Session(会话)

Session 是指用户在与应用进行一段连续交互过程中所形成的会话。这段会话通常包括从用户启动应用到结束使用的所有行为。

一个完整的Session包括一下需要定义的点：

唯一标识：每个 Session 需要有唯一的 ID（如随机生成的token）。

行为触发：某些行为（如启动应用/访问特定页面/登录/从后台切入）开始新的Session。

超时机制：当用户长时间无操作（如 15 分钟）或行为触发后不再有交互，系统会认为该 Session 结束。

Session 数是指在一定时间段内，应用产生的总会话数。例如，某用户在一天内多次打开应用，每次活动都算一个独立的 Session。总计的次数为Session数。

举个例子：

我们设置用户打开app/将app切回前端/产生应用内都定义为“触发行为”。

我们设置闲置时间为30分钟，这之后就定义为“Session结束”。

技术上如何实现Session统计？

我们需要在客户端（Web/移动应用）每次启动应用时生成一个新的 Session ID。在用户活动的持续时间内，将该 Session 关联所有对应的行为。

以一个我写了部分注释的代码为例：

以每次的活跃时间对应一个sessionId及对应的trackActivity；当超时/无活跃数据时，更新lastActivityTime；有新的行为触发时，记录新的sessionId并开始新的session。

```javascript
let sessionId = null; // 空sessionIdlet lastActivityTime = Date.now(); // 设置上次活跃时间为现在
function startNewSession() {    sessionId = generateUniqueSessionId(); // 随机生成一个唯一的 ID    lastActivityTime = Date.now();    console.log(\`New session started: ${sessionId}\`); // 记录一个新的Session}
function trackActivity() {    const now = Date.now();    if (now - lastActivityTime > 30 * 60 * 1000) {  // 超过 30 分钟视为新会话        startNewSession();    } else {        lastActivityTime = now;    }}
function generateUniqueSessionId() {    return \`session_${Math.random().toString(36).substr(2, 9)}_${Date.now()}\`;}
// 应用启动或页面加载时调用startNewSession();
// 模拟用户行为，每次操作都更新活动时间document.addEventListener('click', trackActivity);
```

我们知道除了应用自己本身在记录用户的Session行为，其安装的SDK也在统计应用内的用户行为。比如：应用内安装的归因平台MMP的SDK也在统计用户的Session数/应用内安装的广告聚合平台的SDK也在统计用户的Session数。

那么MMP是如何统计Session数呢？

Appsflyer：通过SDK上报的af\_app\_opened事件来计算session指标。session之间设有最短间隔机制（setMinTimeBetweenSessions），用于调控服务器侧的session判定和统计。流程是：统计到一个session → 开始倒计时 → 倒计时期间上报的session会被忽略。

默认session之间的最短间隔为10分钟。可以设置的范围：1分钟-24小时。上报时间为UTC0时区。

Adjust：通过SDK上报session callback，默认用户打开app30分钟无活跃行为后，视为新的Session。上报时间为UTC0时区。

所以，此时此刻！保证数据的 **逻辑一致性** 就非常重要了！！

保证内部的闲置时间和MMP一致：比如AF与你后台统一设置为10分钟。AJ与你后台统一设置为30分钟。统一选择0时区上报Session数。

聚合平台又是如何统计Session数呢？

聚合平台有自己的单独SDK，一般情况只有请求广告后，才会统计为一个Session。所以上图中，聚合平台当天统计的Session数只有一次。

有数据体量接收数据的广告平台可以通过MMP拉取Session映射到平台的事件，从而计算DAU和RR等指标。

知道了Session的统计逻辑后，我们来看看DAU和RR这两个极为重要的指标在不同的平台是如何计算的：

日活用户DAU：

DAU 通常定义为在一天内至少有一次互动（如启动应用、登录、浏览、点击等）的唯一用户数。在实际开发中，开发者要决定使用什么样的标识符来定义唯一用户。常见的标识符有：

用户 ID（已登录用户）

设备 ID（未登录的用户，可以通过设备标识符来追踪）

Session ID（会话标识符）

一般来说：一个用户ID/一个设备ID+当天有产生至少一个Unique Session ID=一个活跃用户。我们以UTC为时区统计，则为当天的DAU。（最好选择用户ID，因为可以做到一一映射，现在有很大比例拿不到设备ID）

留存率Retention Rate：

对于广告主来说：

留存数为当天的日活用户/总体用户数。所以从逻辑上很好计算。有Session的用户/用户总数。

对于广告平台来说：

分为总体留存数和群组留存数。

总体留存数和广告主侧计算逻辑相同。

群组（cohort）留存数：

将用户首先按照用户安装的日期进行分类，然后看每一天分类的用户，从此刻起的后续事件的留存数。

比如1月1号三个安装用户，2号五个安装用户，3号4个安装用户。

今天是4号。

那么对于1号安装的这一群3个用户来说，目前正在这批用户获取后的第三天内，我们现在能看到的就是RR D2的数据，正在积累D3的数据。

那么对于2号安装的这一群5个用户来说，目前正在这批用户获取后的第二天内，我们现在能看到的就是RR D1的数据，正在积累D2的数据。

那么对于3号安装的这一群4个用户来说，目前正在这批用户获取后的第一天内，我们没有任何成熟的RR数据（你可以说RR D0但是留存看D0没有意义），正在积累D1的数据。

为了衡量广告平台的效果来说，看总体留存数没有意义，看群组数据更有对比意义。
